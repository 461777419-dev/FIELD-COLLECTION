# 图集：通过 GitHub Releases 发布自动更新

当前已配置公开仓库 `461777419-dev/FIELD-COLLECTION`，签名公钥已写入 `update-config.json`。第一次使用请手动安装 v1.0.1；发布 Release 前检查更新会提示找不到版本清单，这是尚未发布的正常状态。鲸鱼娘的动画与搜索表情保留，点击她会打开更新面板并检查版本。

## 用户怎么用

- 拖动“关联图片”区域底部的横条调整高度；高度会保存，切换图片后继续使用。横条获得焦点后可用上下方向键调整，Home 恢复默认高度。右侧详情面板仍可从左边缘拖宽。
- 点击搜索旁的鲸鱼娘检查更新。桌面版默认在启动约 10 秒后检查，之后每 6 小时检查一次；可以关闭自动检查或自动下载。
- 新版自动下载完成后出现提示和鲸鱼娘圆点。点击“安装并重启”，应用退出，再运行已验证的安装包。图库不在安装目录内，升级保留原图库。
- 网页预览可以查看更新面板；安装功能仅 Windows 桌面版可用。

## 第一次配置（只做一次）

1. 建立一个公开 GitHub 仓库，例如 `你的用户名/album-releases`。仓库可以只用于存放安装包，不必公开应用源代码。当前实现不读取 GitHub Token，不支持私有 Releases。
2. 在项目目录运行以下命令。私钥路径的父目录需要已经存在，且路径必须在项目目录之外：

```powershell
node scripts/release-update.cjs init C:/Users/suyao/Documents/album-update-private.pem 你的用户名/album-releases
```

脚本生成 Ed25519 私钥，并把仓库名和公钥写入 `update-config.json`。不要上传私钥或把它打进安装包；备份私钥，丢失后旧版本将无法验证新密钥签署的更新。公钥可以随软件公开发布。

3. 配置完成后重新构建 Windows 安装包，并手动安装这一个版本。此前 v3.0.1 及更旧版本没有更新入口，无法自行获得第一次更新功能。仓库名和公钥必须在这个基础版本构建前固定。

```powershell
$env:CARGO_TARGET_DIR='target-final'
npm run build:win
```

## 每次发布新版

1. 增加 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json` 的应用版本号（格式必须是 `主.次.补丁`，例如 `1.0.1`）。Cargo 会同步自身锁文件中的应用版本。
2. 运行 `$env:CARGO_TARGET_DIR='target-final'
npm run build:win`，生成最新安装包。
3. 设置私钥文件路径，为安装包生成更新清单：

```powershell
$env:ATLAS_UPDATE_PRIVATE_KEY='C:/Users/suyao/Documents/album-update-private.pem'
node scripts/release-update.cjs sign 'src-tauri/target-final/release/bundle/nsis/图集_1.0.1_x64-setup.exe' 'dist/latest.json'
```

可在命令最后加一个 UTF-8 文本文件路径作为更新说明。`latest.json` 包含版本、安装包地址、大小、SHA-256 和签名，无私钥。签名同时保护版本、下载地址、更新说明和文件摘要，下载后及安装前都会复核。

4. 在 GitHub 创建 Release，标签为 `v1.0.1`，将安装包和 `latest.json` 一起作为附件上传。发布为正式 Latest Release，不能是 Draft 或 Pre-release。脚本中的文件名、版本标签必须与上传的一致。
5. 先在测试电脑从上一版走完整个检查、下载、安装和重启流程，再向其他人分发。

应用读取的固定清单地址是：
`https://github.com/你的用户名/album-releases/releases/latest/download/latest.json`

安装包仅允许来自配置仓库的 HTTPS Releases 地址。签名错误、文件损坏、版本未增加或网络失败会停止更新。更新签名与 Windows Authenticode 代码签名是两回事；若希望减少系统对未知发布者的提示，需要另行获得代码签名证书。
